# 00 共通仕様 ― プロジェクトG 工程表変換（設計 A / 設計 B 共通）

本書は設計 A（xlsm 往路）と設計 B（HTML ツール 往路→復路）が**必ず共有する**仕様です。
A と B で CSV の解釈・格子・用語がズレると、復路や他工程表への展開で事故ります。矛盾を見つけたら本書を直し、A・B を追従させてください。

---

## 1. 目的

プロジェクトG（工程管理 SaaS）の工程表を、プロジェクトG を使えない外部業者と往復するための変換基盤を作る。

- **往路**：プロジェクトG が出力する CSV → 業者が読める/直せる形式（xlsx）
- **復路**：業者が直したものを → プロジェクトG に取り込める CSV（元 CSV に差分を上書き）
- 業者は**スマホ・タブレットの Excel** で開く。スマホの Excel は **VBA を実行しない**
- まずは同梱サンプル（サポートルーム、23 工程）を対象にするが、**コードにサンプル固有値を埋めない**（工程数 23、列数 124、行番号範囲、ファイルパス等）

---

## 2. 入力：Sample.zip の中身

| ファイル | 用途 |
|---|---|
| `サポートルーム_サンプル工程表.csv` | 入力 CSV。SHA-256 `FAFDCD5F4802D5B36316047C2B7B42F0F4CB3244DA11EB041DF254FBDB8481B9` |
| `サポートルーム_サンプル工程表.pdf` | プロジェクトG が出力した正式印刷（A3 横 2 頁）。**見た目の正本** |
| `画面スクショ遠景.png` | プロジェクトG の画面（表示期間 2026/09/01–09/30、ズーム 67%） |
| `0902から1009_*_近景.png` ×3 | プロジェクトG の画面の拡大（行 5–27、15–35、36–47） |

**PDF と PNG は、往路の出力を検収するための正解画像です。** 実装セッションはこれらを必ず開いて確認すること。

## 3. CSV 仕様（実測）

### 3.1 ファイル形式

- UTF-8 **BOM 付き**、改行 CRLF
- RFC 4180 準拠の引用（`工程線名` などに JSON が入り、カンマ・二重引用符を含む）。**単純な `Split(",")` は不可**
- 構造：

| 行 | 内容 |
|---|---|
| 1 | メタ見出し 7 列：`プロジェクトID, 工程表ID, 工程表の期間, 工程表の最終更新日, 最終更新ユーザーID, 最終更新ユーザー名, 工程表の最終更新バージョン` |
| 2 | メタ値。`工程表の期間` は `2026/09/01-2026/11/30` 形式（ハイフン区切り、両端含む） |
| 3 | 工程データ見出し **124 列**（サンプル時点。**列数は固定と仮定しない。見出し名で引く**） |
| 4〜 | 工程 1 行 1 工程。サンプルは 23 行 |

### 3.2 工程 = ノード間のエッジ

プロジェクトG は**ネットワーク工程表**である。

- **項目 ＝ ノード ＝ 行**。`項目ID（開始日ノード）` / `項目ID（終了日ノード）`、`項目名（〜）`、`開始日の行番号` / `終了日の行番号`
- **工程 ＝ エッジ**。開始ノードから終了ノードへ引く線。`工程ID` で一意
- **ノードは共有される**。例：A1 の終了ノード ＝ A2 の開始ノード（同じ `項目ID`）。B1→B2→B3、C1→C2→C3、D1→…→D5 も数珠つなぎ
- 1 本の工程が**行をまたぐ**（例 C1：開始行 21、終了行 17）。折れ線・斜行はその結果

### 3.3 使用する列と解釈

| 列名 | 型 | 解釈 |
|---|---|---|
| `工程ID` | 文字列 | 工程の一意キー。**復路の突き合わせキー** |
| `項目ID（開始日ノード）` `項目ID（終了日ノード）` | 文字列 | ノード ID。共有判定に使う |
| `項目名（開始日ノード）` `項目名（終了日ノード）` | 文字列 | 行見出し。**空のことがある**（無名ノード） |
| `開始日の行番号` `終了日の行番号` | 整数 | プロジェクトG の行番号（1 起点）。サンプルは 5〜46 |
| `開始日` | ISO 日時 `2026-09-07T00:00:00+09:00` | **日付部分のみ**使う |
| `終了日` | ISO 日時 `2026-09-14T23:59:59+09:00` | **日付部分のみ**使う。**終了日を含む** |
| `工程線名` | JSON 配列（1 要素） | `[{"name":"A1","textSize":"L",…}]`。`name` を表示名に使う。キー一覧：`id, name, nameAlignment, nameBold, nameColor, namePosition, namePositionCoefficient, namePositionWithinOptions, nameWritingMode, showContentsDaysWithLineBreak, showLeaderLine, showNameOnLine, showTotalDays, showWorkingDays, textSize` |
| `工程線の形状` | 列挙 | `straight, xElbow, yElbow, crank, gate, boxS, boxM, boxL, barAutoAdjust, barProcessNameAdjust` |
| `工程線の矢印` | `arrow` / `none` | 終端矢印 |
| `実線・点線` | `` / `dash` | 空 = 実線 |
| `工程線の太さ` | 数値 or 空 | 空 = 既定（2） |
| `工程線の色` | `#rrggbb` or 空 | 線色 |
| `工程線の背景色` | `#rrggbb` or 空 | 塗り色（box/bar） |
| `工程線の斜行` | `` / `true` | true なら折れ線の縦部分を斜線で描く |
| `項目ID（中間ノード）` `中間ノード日付` | 文字列 / ISO 日時 | gate / crank の縦線位置。サンプルは 5 件 |
| `休日` | 整数 | 期間内の非稼働日数。**表示は日付から判定する（土日）。この列は検算用** |
| `延べ日数` `日数` `調整日数` | 整数 | 派生値。復路で再計算対象（規則は プロジェクトG 側確認待ち） |
| `0.5日` | 空 | サンプルは全件空。**未対応と明記し、値があれば警告** |
| `工程削除` | 空 | サンプルは全件空。値があれば描画しない |
| `開始日ノード形状` `終了日ノード形状` | `` / `none` | `none` ならノード丸を描かない（bar 系） |
| `開始日ノードの依存タスク（行程ID、依存関係）` 等 | JSON | `[{"id":工程ID,"dependency":"FS"|"SF"}]`。往路では描画任意、復路で検証に使う |
| `開始日ノードの関係線名` 等 | 文字列 | 関係線（例「関係１」）。往路では描画任意 |
| `詳細工程1〜6 …` | 各種 | 業者が直す可能性がある（人数/台数、協力会社）。**往路 v1 では出力しない**。復路で扱う列は別途合意 |

### 3.4 サンプルの実測値（検収に使う）

| 項目 | 値 |
|---|---|
| 工程数 | 23 |
| 形状分布 | yElbow 3, gate 5, straight 3, boxM 1, boxL 1, barAutoAdjust 2, barProcessNameAdjust 1, crank 3, boxS 1, xElbow 3 |
| 線幅 | 既定 20 件、2.5 が 2 件、1 が 1 件 |
| 矢印 none | 2 件（C3, D5） |
| 斜行 true | 2 件 |
| 中間ノードあり | 5 件（全て gate/crank） |
| 行番号範囲 | 5〜46 |
| 工程表の期間 | 2026/09/01–2026/11/30（CSV メタ）。PDF は 09/01–10/30 で印刷されている |

## 4. カレンダー・格子の定義

| 用語 | 定義 |
|---|---|
| 表示期間 | 利用者が指定する `Start` ≤ `End`（両端含む）。CSV メタの `工程表の期間` の範囲内であること |
| 日付列 | `Start` から `End` まで 1 日 1 列 |
| 日付 index | `n = (日付 − Start) の日数`。`Start` が 0 |
| 開始境界 | `開始日` の列の**左端** |
| 終了境界 | `終了日 + 1 日` の列の**左端**（終了日を含むため） |
| クリップ | 表示期間をはみ出す工程は期間内に切る。完全に期間外なら描かない |
| 休日 | **土曜・日曜**。プロジェクトG の画面では灰色列。祝日は本サンプルでは考慮しない（拡張点として残す） |
| 行 | プロジェクトG の行番号 `r` をそのまま使う。**空行も再現する**（行見出しの位置が プロジェクトG/PDF と一致すること） |

### xlsx での配置（設計 A・B 共通）

| 位置 | 内容 |
|---|---|
| 行 1 | 月見出し（同じ月の日付列を結合、`m月`） |
| 行 2 | 日 `d` |
| 行 3 | 曜日 `aaa` |
| 行 `r + 3` | プロジェクトG の行番号 `r` の行 |
| A 列 | 行見出し（その行にノードを持つ `項目名`。複数あれば `/` 連結、空なら空） |
| B 列以降 | 日付列。`Start` が B 列。日付 index `n` → 列 `2 + n`（1 起点） |
| 土日列 | 背景を薄灰 |

## 5. プロジェクトG の描画規則（PDF・PNG からの読み取り）

設計 B の SVG 描画が従う規則。設計 A は 5.1 の「位置」だけ使い、形状は落とす。

### 5.1 位置

- 線の始点 x ＝ 開始境界、終点 x ＝ 終了境界
- 行 `r` の y ＝ その行の中央
- **稼働日は実線、土日は点線**（1 本の線の中で切り替わる）
- 線の両端に白丸ノード（`ノード形状 = none` を除く）
- `工程線名` は線の上に、`textSize` に応じた大きさで

### 5.2 形状（観測に基づく。実装セッションは PDF で全 23 件を照合すること）

| 形状 | 観測された描き方 | 例 |
|---|---|---|
| straight | 始点と終点を直線で結ぶ。行が違えば**斜線** | E1（同行）、E2/E3（行違い＝斜線） |
| yElbow | **始点で縦**→終点行で横 | A1, A2, A3 |
| xElbow | 始点行で横→**終点で縦** | B1, B3 |
| crank | 縦→横→縦。横は中間の行 | C1（21→19→17） |
| gate | 縦→横→縦。横は終了行、最後の縦で終了ノード行へ | D4 |
| 斜行 = true | 上記の「縦」部分を斜線にする | B2, C3 |
| boxS / boxM / boxL | 両端が尖った六角形の**枠線**。S<M<L で高さが違う | バー1, バー2, バー3 |
| barAutoAdjust | 塗りつぶし矩形 | バー4, バー5 |
| barProcessNameAdjust | 細い塗りバー、名前は上 | バー6 |
| 関係線 | 縦の点線で 2 ノードを結ぶ | 関係１ |

crank / gate の縦線の位置は、`中間ノード日付` があればそこ、なければ実装側で PDF に合わせる。**`(開始+終了)/2` の決め打ちは不可**（奇数日でセルの真ん中に落ちる）。

---

## 6. 意図的に落とすもの（設計 A の xlsx）

xlsx（業者用）は**ネットワークのガント投影**である。以下は業者が編集できない構造なので、xlsx では描かない。これは設計上の決定であり、欠陥ではない。

- 折れ線・斜行・crank/gate の縦線
- ノードの白丸
- 依存関係・関係線
- 工程線名の位置・サイズ指定（バー先頭に表示するだけ）

---

## 7. 業者が編集してよいもの（往路 v1 の前提。復路で確定）

- `開始日`、`終了日` のみ
- それ以外は**保護**。ID・行番号・形状・色は業者に見せる必要もない

---

## 8. 禁止事項（46 版の失敗から）

1. **サンプル固有値をコードに埋めない**（`EXPECTED_ROWS = 23`、`EXPECTED_HEADERS = 124`、絶対パス、行番号範囲）
2. **バーを Shape（図形）で描かない**。セル塗り・罫線・条件付き書式か、SVG で描く。Shape はセル格子と座標系が違い、DPI・保存・アンカー量子化で必ずズレる
3. **入力 CSV・基準ファイルを上書きしない**。出力は常に別名
4. **目視だけを合格条件にしない**。セル値・CSV 値で機械検査できる条件を必ず併記する
5. 列は**見出し名で引く**。列番号決め打ち禁止
6. 復路で扱わない列は**バイト単位で元 CSV のまま**出力する

## 9. 用語

| 用語 | 意味 |
|---|---|
| 監督 | プロジェクトG を使える社内担当。往路・復路のツールを操作する |
| 業者 | プロジェクトG を使えない外部協力会社。xlsx を受け取り日程を直す |
| 往路 | CSV → xlsx |
| 復路 | 業者が直した xlsx → CSV |
| 格子 | 行（プロジェクトG の行番号）× 日付列 |
