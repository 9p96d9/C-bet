# ファイル仕様書（人が読む用）

もう 1 冊の `ファイル仕様書_チャットAI用.md` は、どのファイルがどの名前を
出していて誰が使っているか、という**機械的な事実**だけを載せている。
あちらはコードから自動で作っているので、必ず正しい。

こちらは逆に、**なぜそうなっているか**と、**直すときに何を気にすればいいか**を書く。
手で書いているので、コードと食い違ったら**コードとあちらが正**。

---

## 1. まず知っておくこと

### 納品するのは 1 枚の HTML、開発するのは 9 個のファイル

現場に渡すのは `プロジェクトG_工程表ツール.html` 1 枚だけ。1,065,284 文字ある。
このうち **947,702 文字（89.0%）は ExcelJS**（xlsx を書くための外部ライブラリ）で、
自分たちが書いたのは JS が 107,668 文字、`shell.html` が 8,428 文字。
（`node tools/build-html.mjs` のたびに変わるので、桁だけ見ておけばよい）

1 枚に入っているのは、次の 9 個を順番に並べただけ。

```
src/shell.html        ← 画面の骨組みと CSS
  src/00-holiday.js     休日の判定
  src/01-csv-model.js   CSV を読む
  src/02-geometry.js    座標を出す
  src/03-render.js      SVG を描く
  src/04-xlsx.js        xlsx を作る
  src/05-verify.js      描いたものを検査する
  src/07-diag.js        診断ログ
  src/06-ui.js          ボタン・入力欄
```

**106 万文字の中の 1 行を直すのは無理がある。**
だから直すときは `src/` の中の 1 ファイルだけを開いて、直して、また 1 枚に戻す。

### 3 つの道具

| 使うもの | いつ | Node が要るか |
| --- | --- | --- |
| `tools/開発用.html` | 直した結果をすぐ見たいとき | **要らない** |
| `tools/組み立て.html` | 1 枚に戻すとき／1 枚をばらすとき | **要らない** |
| `tools/*.mjs` `tools/*.py` | 検査を一括で回すとき | 要る |

現場の PC に Node が入っていなくても、**上の 2 つだけで一周できる**。

## 2. 直すときの一周

```
┌─ 1 枚の HTML しか手元に無い ─┐
│  tools/組み立て.html で「分解」 │ → src.zip が落ちてくる
└───────────────┘
            ↓
   src/○○.js を 1 個だけ、チャット AI に渡して直してもらう
   （ファイルの先頭の「自動生成」の枠ごと渡す。あれが前後関係の説明になる）
            ↓
   tools/開発用.html をブラウザで開いて、CSV を読ませる
   → 画面下のログに NG が 1 つも無ければ OK
            ↓
   tools/組み立て.html で「組み立て」
   → プロジェクトG_工程表ツール.html が落ちてくる
            ↓
   落ちてきた 1 枚をブラウザで開いて、もう一度 CSV を読ませて確かめる
```

**最後の確認を飛ばさないこと。** 組み立ては機械がやるが、
`shell.html` の CSS を直したときなどは、見た目が変わるのは組み立てたあとになる。

### チャット AI に渡すときの注意

- **1 ファイルまるごと渡す。** 先頭の「自動生成」の枠には、そのファイルが
  他から借りている名前と、他に使われている名前が書いてある。
  AI はそれを読んで「この名前は定義し直さなくていい」と分かる。
- **枠に載っている「他が使っている名前」は変えさせない。** 変えると連結した先で落ちる。
- **`import` / `export` を書かせない。** `file://` では読めない。
- **`fetch` や URL を書かせない。** `tools/組み立て.html` が組み立てを断る。
- 返ってきたコードは、**必ず `tools/開発用.html` で動かしてから**組み立てる。

## 3. データはどう流れるか

```
CSV ファイル
  │  01-csv-model.js : parseCsv() → buildDocument()
  ↓
Document { meta, processes[], headings[] }
  │  processes[] の 1 件 = 工程 1 本
  │    { id, name, shape, startNode{row,date}, endNode{row,date},
  │      gateRow, color, weight, arrow, dash, nameSpec, deleted }
  │
  ├─→ 02-geometry.js : makeGeometry() で格子 → shapeOf() で折れ方
  │     ↓
  │   03-render.js : render() で <svg> を組み立てて画面へ
  │     ↓
  │   05-verify.js : verifySvg() が描いた DOM の属性を読み戻して検査
  │
  └─→ 04-xlsx.js : buildWorkbook() で xlsx
        ↓
      05-verify.js : verifyXlsx() が書いたバッファを読み戻して検査
```

**大事な考え方**：検査は「描いたときに使った値」を使い回さない。
描いた結果（DOM の属性、xlsx のバッファ）を**読み戻して**、
期待値は CSV から**もう一度計算し直して**突き合わせる。
そうしないと「間違った値で描いて、同じ間違った値で検査して、OK」になる。

### 座標の決まり方

```
x = （表示開始日から数えて何日目か） × DAY_W        DAY_W = 24px
y = （行番号 − 1） × ROW_H + ROW_H / 2             ROW_H = 28px
```

行番号は CSV の `項目行番号（開始日ノード）` `項目行番号（終了日ノード）` そのもの。
つまり **絵の縦位置は CSV が決めていて、ツールは計算していない**。

## 4. ファイルごとの注意

### `00-holiday.js` — 休日

上位仕様の 4 章は「祝日は考慮しない」と書いてあるが、**それは実物と合わない**。
サンプルの PDF の灰色列と、CSV の `休日` 列 23 件が、
どちらも「土日＋祝日」でないと説明がつかなかった。だから祝日も休みとして数えている。

祝日は法律どおりに計算している（ハッピーマンデー、振替休日、国民の休日、
春分・秋分の近似式、2019 年の即位礼、2020・2021 年の五輪移動を含む）。
**近似式が使えるのは 1980〜2099 年**で、外れると画面に注意が出る。

会社独自の休み（年末年始・盆）を足したいときは `isNonWorkingDay()` に足す。
ただし xlsx の `NETWORKDAYS` に渡す祝日一覧（`04-xlsx.js` の `publicHolidaysIn()`）も
同時に直さないと、画面と Excel で日数が食い違う。

### `01-csv-model.js` — CSV

- **列は必ず列名で引く。列番号は使わない。** 列名は `COL` にまとめてある。
  別の現場の CSV で列名が違ったら、ここだけ直せばよい。
- CSV に値が無くてツールが埋めたところは、**全部 `recordEstimate()` に残す**。
  画面下の一覧と［推定を表示］の目印はここから出ている。
  新しく「無ければこうする」を足すときは、必ず記録も足すこと。
- `gateRowByRule()` は**確実に正しいわけではない**。
  CSV には gate の中間ノードの行番号が入っていないので、
  「帯の外側で空いている最初の行（下を優先）」という規則で埋めている。
  サンプル 2 件のうち当たったのは 1 件だけ。
  現場の工程表で位置がおかしいときは、画面の「gate 中間行の指定」で上書きできる。

### `02-geometry.js` — 座標と形状

ここの数字はほぼ全部 **PDF から実測した値**で、勘で決めたものではない。
根拠は `設計B_実装メモ.md` の 3 章に表で載っている。
`H_RATIO` などは px ではなく **行の高さに対する比率**で持っているので、
`ROW_H` を変えても図形の見た目の比率は崩れない。

形状を足すときは `SHAPE_RULES`（折れ方）と `SHAPE_KIND`（線か箱か帯か）の
**両方**に足す。片方だけだと描かれずに黙って消える。

### `03-render.js` — SVG

`render()` は**毎回まっさらから作り直す**。部分更新はしない。
遅くなりそうに見えるが、500 工程でも十分速く、
「前の描画が残って混ざる」事故が起きないほうが大事。

座標は `num()` を通して小数第 3 位で丸めて書く。
**検査が属性値を読み戻して比べるので、書式を変えると検査が落ちる。**

### `04-xlsx.js` — xlsx

上位仕様の 2 つの文書が xlsx の配置について食い違っている。
（4 章は「行 = 工程表の行」、設計B 5.3 は「行 = 工程 1 本」と読める）
**1 工程 = 1 行**を選んだ。理由は `設計B_実装メモ.md` の該当章に書いた。
同じ開始行を持つ工程が 2 本あると、行を共有させたときに開始日・終了日を持てなくなるため。

曜日のセルは書式 `aaa` を使っている。これは上位仕様の指定どおりだが、
**ExcelJS も openpyxl もこれを日付と見なさない**ので、
読み戻すとシリアル値（46266 など）が返る。検査はそれを承知で書いてある。
「曜日が数字になっている」と報告が来ても、Excel で開けば正しく曜日で表示される。

### `05-verify.js` — 検査

ここに項目を足すのは歓迎。`pushResult(list, ok, ...)` で 1 件積むだけ。
**ただし期待値を「描画に使った変数」から取らないこと。** CSV から計算し直す。

### `07-diag.js` — 診断ログ

現場でうまくいかないときに、**工程表の中身を外に出さずに**原因を追うためのもの。
工程 ID は `P001`、項目名は `(5文字)` のように置き換えている。
`tools/diag-test.mjs` が「CSV から拾った機微な文字列が 1 つも入っていないこと」を
毎回確かめている。**ログに新しい項目を足したら、このテストも通ることを確認すること。**

### `06-ui.js` — 画面

他の全部をここから呼ぶ。逆に**ここの名前は誰も使っていない**ので、
中身は比較的自由に変えられる。
ボタンや入力欄そのものを足すときは `src/shell.html` も直す。

### `src/shell.html` — 骨組みと CSS

`/*__EXCELJS__*/` と `/*__APP__*/` の 2 つが差し込み口。
**この 2 つを消すと組み立てられなくなる**（`tools/組み立て.html` が止める）。

## 5. 検査の回し方（Node がある環境）

```
node tools/build-html.mjs        1 枚の HTML と 開発用.html を作る
node tools/acceptance.mjs        受け入れ 1〜5
node tools/dev-check.mjs         開発用.html と 1 枚が同じ結果になるか
node tools/assemble-check.mjs    組み立て.html が Node と同じ HTML を作るか
node tools/holiday-test.mjs      祝日の計算
node tools/diag-test.mjs         診断ログに中身が漏れていないか
node tools/robustness-test.mjs   壊れた CSV・大きい CSV
python3 tools/compare-pdf.py --manual   PDF と 1 本ずつ突き合わせ
python3 tools/verify-xlsx-independent.py  openpyxl で xlsx を読み直す
```

仕様書とヘッダーを作り直すのは次の 3 つ。**コードを直したら必ず回す。**

```
node tools/analyze-src.mjs    依存関係を数え直す
node tools/gen-headers.mjs    src/*.js の先頭の枠を書き直す
node tools/build-spec.mjs     ファイル仕様書_チャットAI用.md を作り直す
```

`node tools/gen-headers.mjs --check` は、書き換えずに「古くなっていないか」だけを見る。

## 6. 設計でわざとそうしたところ

| そうしたこと | 理由 |
| --- | --- |
| 8 ファイルを連結して 1 スコープに置く | `file://` で ES モジュールは CORS で読めない。`<script src>` なら読めるので、開発時と納品時で同じ形にできる |
| ファイルの先頭の枠を自動生成にした | 手で書いた依存関係は必ずズレる。ズレた案内板はチャット AI を確実に誤らせる |
| 番号を振ったファイル名にした | 連結する順番＝依存の順番。名前を見れば「01 は 03 の名前を使えない」と分かる |
| 検査を読み戻し方式にした | 描いた値をそのまま検査に使うと、間違いが検査をすり抜ける |
| 推定を記録して画面に出す | CSV から決められない値があることを、使う人に隠さないため |
| ExcelJS をそのまま同梱した | xlsx の書き出しを自作すると、条件付き書式・数式・書式の再実装が要る。バグの持ち込み先としては割に合わない |
| 組み立てをブラウザでもできるようにした | 現場の PC に Node が入っていないため |
