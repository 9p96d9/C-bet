### P-01 一般互換性検査ツールがXLSM非対応

- 事象: 使用可能な一般互換性検査ツールへXLSMを渡すと、対象形式外として終了する。
- 再現条件: `.xlsm`を検査対象に指定する。
- 期待結果: XLSMの互換性検査を実行できる。
- 実結果: 対応形式が `.pptx`、`.docx`、`.xlsx`に限定され、XLSMは検査不能。
- 影響: 当該ツールによるExcel互換性判定はできない。
- 代替確認: 同梱の専用 `verify_xlsm.py` によるパッケージ、VBA、埋め込みソース検査を実施し、全項目合格。
- 修正要否: 生成コードの不具合ではない。Windows版Excelによる実機確認が必要。
- 状態: 確認不能を代替検査へ分岐。

### 8.2 主障害 P-02

#### 事象

「変換実行」ボタンを押すと、Microsoft Visual Basic for Applicationsのダイアログが表示され、処理が停止する。

#### 表示メッセージ

```text
非表示モジュール内でコンパイル エラーが発生しました。
通常このエラーは、コードがこのアプリケーションのバージョン、プラットフォーム、
またはアーキテクチャと互換性がない場合に発生します。
':,"textSize":"L","namePositionWithinOptions":"lineNameUpperCenter"'
```

末尾はCSVの「工程線名」列に含まれるJSON断片と一致する形式であり、本来のVBAモジュール名ではない。

#### 再現手順

1. `プロジェクトG変換ツール.xlsm`をWindows版Excelで開く。
2. VBAマクロを有効化する。
3. VBAProjectを手動コンパイルする。ここではエラーなし。
4. 「CSV選択」で同梱サンプルCSVを選択する。
5. Start／Endが自動入力されたことを確認する。
6. 「変換実行」を押す。
7. 上記エラーが表示される。

#### 期待結果

CSVを読み込み、工程表XLSXおよび`変換ログ.txt`をCSVと同じフォルダーへ生成する。

#### 実結果

エラーダイアログが表示され、XLSX、`変換ログ.txt`とも生成されない。

#### 再現性

2回再現。

- A-1.0.0: 再現
- A-1.0.1-diagnostic: 再現

診断版では公開関数名`Convert`を`ConvertProjectG`へ変更したが、エラー内容と発生位置は変わらなかった。したがって関数名衝突説は棄却する。

#### 影響範囲

- XLSMの起動、CSV選択、期間読込みまでは利用可能。
- 主目的であるCSVからXLSXへの変換は利用不能。
- 本番利用不可。

#### 原因判定

未確定。ただし、通常のVBAソース構文エラーだけでは説明しにくい。

優先して確認すべき箇所:

1. 独自生成した`vbaProject.bin`のモジュール識別情報
2. `VBA/dir`内のMODULEレコード列
3. `PROJECTwm`のANSI名とUnicode名の対応および終端
4. MODULEOFFSETと各モジュールストリーム内のソース開始位置
5. Excelが実行時コンパイル時に参照するPerformanceCache等の未生成領域
6. CSV文字列がモジュール名として表示されるに至るメモリ／ストリーム境界の破損

#### 開発者への推奨切り分け

1. Windows版Excelが正規生成した最小XLSMへ同じ8モジュールを手動インポートし、同じCSVで実行する。
2. 正規XLSMで動けば、VBAコードではなく独自`vbaProject.bin`生成経路の不具合と確定できる。
3. 1モジュールだけの最小マクロから開始し、モジュールを段階追加して、独自生成VBAの実行時コンパイル可否を確認する。
4. `SelectCsv`が動くことを利用し、`RunConversion`から呼ばれるモジュールを順番に外して最初に破損認識されるモジュールを特定する。
5. Excelが正規保存した`vbaProject.bin`と独自生成版を、CFBストリーム構成、dir展開結果、PROJECT、PROJECTwm、各モジュールストリームの単位で比較する。
