# 00 — ビジョンと前提（Vision & Premises）

> このファイルは資料そのものではなく、**資料をつくるための設計書**です。
> 実装（Opus）はこの定義に従ってコンテンツを増築します。

---

## 0. プロジェクト名

**『3歳までの土台づくり大全』**
— 父親が、娘の潜在能力を科学的根拠に基づいて引き上げるための体系的リファレンス。

- コードネーム: `foundations`
- 対象読者: **父親**（0歳1ヶ月の娘を持つ）。妻は保育士。
- 対象期間: **受胎後〜満3歳（0〜36ヶ月）**。中心は 0〜36ヶ月。

---

## 1. なぜ作るのか（Why）

依頼者の状況と要望を、設計要件として明文化する。

| 依頼者の言葉 | 設計要件への翻訳 |
|---|---|
| 妻は保育士。基本的なことは完璧にできる前提でOK | **「基本的育児（授乳・寝かしつけ・衛生・安全・生活リズム）」は扱わない。** それらを土台に、**能力開発（enrichment）に特化**する |
| 娘の潜在的な能力を引き上げたい | 発達を「底上げ」する高レバレッジ介入に絞る。**万人向けの網羅ではなく「効くもの」を優先** |
| 若い時ならではの絶大な効果 | **敏感期（sensitive periods）と脳の可塑性**を科学的に扱う。ただし神話（"窓は閉じる"式の煽り）は明確に否定する |
| 勉強やスポーツが得意な子に | **学業予測因子（実行機能・言語・数量認知）**と**身体リテラシー（physical literacy）**を二本柱にする |
| 父である僕ができること | **父親という役割の固有の強み**を軸にする（母親の代替ではなく差別化） |
| 2000ページ以上の完全版、図も豊富 | **拡張可能なデータ駆動サイト**として設計し、Opusが大量のカード／章を追加できる土台を作る |

## 2. 核となる編集方針（Editorial Stance）

このプロジェクトの信頼性は、以下の姿勢を貫けるかで決まる。

1. **正直さ > 煽り。**
   「これをやれば天才に」式の断定はしない。効果量が小さいこと・不確実なことは、そう書く。
   親の不安を煽って商品化された早期教育（フラッシュカード大量暗記、乳児向け知育DVD等）は、**根拠に基づいて明確に「非推奨」と表示**する。

2. **土台 > テクニック。**
   個別の「知育メソッド」より、あらゆる能力の共通基盤（愛着・応答的やりとり・睡眠・運動・言語環境・自己制御）を最優先する。**共通基盤への投資が、最も効果量が大きく、最も可塑性が高い。**

3. **関係性 > 成果。**
   「賢い子にする」ための介入が、親子関係や子の内発的動機を損なうなら本末転倒。すべての活動は「楽しい親子のやりとり」として成立することを要件にする。

4. **父親の固有性を活かす。**
   父親関与には、母親関与とは統計的に区別される寄与（ラフ＆タンブル遊びによる情動調整、探索の"安全基地"、言語入力の質的差異など）がある。これを中核テーマにする。

5. **エビデンスは等級で示す。**
   すべての主張に**エビデンスレベル（A〜D）**を付す（→ `05-evidence-policy.md`）。読者が「どれくらい信じてよいか」を一目で判断できるようにする。

## 3. スコープ（含む／含まない）

### 含む（In Scope）
- 発達科学の土台（脳の可塑性・敏感期・愛着・ストレス・睡眠・栄養・運動と認知）
- 父親の役割の科学
- 発達ドメイン別の深掘り（言語／粗大運動・スポーツ／微細運動／数量・空間／実行機能／音楽／感覚／社会情動／好奇心・遊び／読み聞かせ）
- 月齢ロードマップ（0〜36ヶ月、マイルストーン＋高レバレッジ活動）
- 実践アクティビティ図鑑（父親が今日できること）
- 環境デザイン（玩具・絵本・スクリーン方針・家庭の設え）
- 神話と落とし穴の是正
- 発達の記録と「受診の目安（赤旗サイン）」
- 用語集・参考文献

### 含まない（Out of Scope）
- 授乳・離乳食の栄養設計、寝かしつけ手技、病気対応 → **医療・基本育児は妻および専門職の領域**
- 医療的診断・治療の指示（本資料は情報提供であり医療助言ではない）
- 特定商品・教室の宣伝

## 4. 成果物の形（Deliverable Form）

- **ブラウザで見る、体系的でリッチな静的サイト**。
- **データ駆動**：コンテンツは構造化データ（Markdown＋frontmatter / JSデータ）として持ち、ビルドスクリプトが静的HTMLを生成する。→ 章・カードを足すだけで「ページ数」がスケールする。
- **依存ゼロで動く**：`node build/build.mjs` だけでビルドできる（外部npmパッケージ不要）。オフライン・長期保守に強い。
- **図を多用**：SVGダイアグラム／タイムライン／カード／表を標準コンポーネント化し、文章だけにしない。

「2000ページ」は物理ページ数ではなく、**"完全版"の情報密度と網羅性**の比喩と解釈する。設計上、アクティビティカード・月齢エントリ・ドメイン節を追加するほど自然にページが増える構造にしておくことで、この規模要求に応える。

- [ ] エビデンスレベルが付与されている
- [ ] 「なぜ効くか（科学的根拠）」が1つ以上の具体的機序で説明されている
- [ ] 「父親が具体的に今日できること」に落ちている（抽象論で終わらない）
- [ ] 安全上の注意が必要な場合は明記されている
- [ ] 神話・過剰主張を含まない（含むなら是正として明示）
- [ ] スキーマ（`02-content-schema.md`）に準拠している
- [ ] 関連コンテンツへのリンクがある（孤立させない）
